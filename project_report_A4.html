Abstract

Numerical integration of nonlinear flight equations of motion—such as classical fourth-order Runge-Kutta (RK45) routines for ballistic projectiles subject to quadratic aerodynamic drag—incurs non-negligible computational overhead, severely limiting its utility in real-time guidance, swarm trajectory prediction, and low-power embedded avionics. This project presents the Instant Flight Trajectory Predictor, a full-stack Machine Learning surrogate framework capable of predicting five critical flight parameters (Range, Max Altitude, Flight Time, Apex X, and Impact Speed) in under 0.27 ms, representing a 4x to 21x speedup over numerical ODE solvers. Trained on a 5,000-sample flight dataset spanning velocities from 20 to 300 m/s, launch angles from 5° to 85°, and masses from 0.5 to 50 kg, our proposed physics-informed polynomial ridge regression model achieves R² > 0.999 with a Mean Absolute Error of 22.3 m across multi-kilometer trajectories. The system is deployed via an asynchronous FastAPI backend and a responsive dark-mode aerospace telemetry web application featuring live asymmetric power-spline trajectory reconstruction, physical bound clamping, and interactive Runge-Kutta audit verification.

1. Problem Statement & Objectives

1.1 Problem Definition

In classical exterior ballistics and atmospheric flight dynamics, a point-mass projectile traveling through the air experiences downward gravitational acceleration and quadratic aerodynamic drag. The governing equations of motion form a coupled non-linear system of second-order differential equations:

dx/dt = vx,      dy/dt = vy
dvx/dt = -(kdrag / m) · v · vx
dvy/dt = -g - (kdrag / m) · v · vy

where v = √(vx² + vy²), g = 9.81 m/s², and the lumped aerodynamic drag parameter is defined by kdrag = 0.5 · ρ0 · Cd · A = 0.003675 kg/m (with sea-level air density ρ0 = 1.225 kg/m³, sphere drag coefficient Cd = 0.30, and cross-sectional area A = 0.02 m²).

Because quadratic velocity terms cannot be solved in elementary closed-form analytical integrals, ballistics analysts must rely on iterative step-by-step numerical solvers (e.g., Runge-Kutta RK45, ode45). When thousands of trajectories must be evaluated concurrently—such as in Monte Carlo dispersion analyses, real-time fire-control interception, and autonomous UAV path planning—numerical integration forms an unacceptable computational bottleneck.

1.2 Technical & Aerospace Relevance

  • High-Frequency Interception: Counter-rocket, artillery, and mortar (C-RAM) interception systems require millisecond decision latency; integration delays directly degrade interception probability.
  • Edge Avionics Constraints: Lightweight micro-UAVs and guided munitions rely on resource-constrained microcontrollers with limited floating-point units.
  • Digital Twin & Simulation: Interactive flight simulators require instant recalculation of flight paths as aerodynamic parameters are adjusted by operators.

1.3 Project Objectives

  1. Synthetic Dataset Generation: Implement event-driven MATLAB (ode45) and Python (scipy.integrate.solve_ivp) numerical pipelines with ground-impact and apex event detectors across 5,000 distinct flight regimes.
  2. Physics-Informed ML Surrogates: Formulate custom feature transformations that capture aerodynamic invariants (v·sinθ, v·cosθ, sin 2θ, ln m, 1/m) to attain an R² ≥ 0.99.
  3. Deterministic Physical Clamping: Guarantee that ML predictions never violate physical boundaries (0.05 m ≤ Pred ≤ Analytical Vacuum Boundary).
  4. Continuous Spline Path Synthesis: Develop an asymmetric power spline algorithm that reconstructs continuous flight curves from discrete predictions without numerical steps.
  5. Full-Stack Telemetry Web System: Deploy an interactive dark-mode telemetry dashboard served via FastAPI and published globally on GitHub Pages.

2.2 Dataset Specifications

The training dataset comprises 5,000 systematically gridded trajectories generated via high-precision numerical integration (rtol=10-6, atol=10-8):

  • Velocity (v0): 20 to 300 m/s (20 uniform steps)
  • Launch Angle (θ): 5° to 85° (25 uniform steps)
  • Projectile Mass (m): 0.5 to 50.0 kg (10 log-spaced steps: 0.5, 0.83, 1.39, 2.32, 3.87, 6.46, 10.77, 17.97, 29.97, 50.0 kg)
  • Target Outputs (5): Landing Range (m), Peak Altitude (m), Flight Time (s), Apex X coordinate (m), and Impact Speed (m/s).

2.3 Physics-Informed Feature Engineering

Standard regression models trained purely on raw inputs [v, θ, m] fail to capture the exponential and trigonometric relationships of ballistic motion. We engineered a 10-dimensional basis:

Φ(X) = [v, θrad, m, ln(m), 1/m, sin(θ), cos(θ), sin(2θ), v·cos(θ), v·sin(θ)]

Aerodynamic Rationale: The term sin(2θ) isolates the principal component of vacuum range; 1/m governs acceleration loss since drag deceleration scales inversely with mass (adrag = -k·v²/m); and v·cos(θ) / v·sin(θ) represent decoupled orthogonal velocity vectors.

3. Implementation & Code Snippets

3.1 Physics Constants & Feature Expansion (backend/physics.py)

import numpy as np

G = 9.81          # Gravitational acceleration (m/s²)
RHO0 = 1.225      # Sea-level atmospheric density (kg/m³)
CD = 0.30         # Ballistic drag coefficient
A_AREA = 0.02     # Cross-sectional area (m²)
K_DRAG = 0.5 * RHO0 * CD * A_AREA   # Lumped constant = 0.003675 kg/m

def physics_feature_expansion(X: np.ndarray) -> np.ndarray:
    """Transforms raw inputs [velocity, angle_deg, mass] into a 10-D physics basis."""
    v = X[:, 0]
    ang = X[:, 1]
    m = X[:, 2]
    angle_rad = np.radians(ang)
    return np.column_stack([
        v, angle_rad, m,
        np.log(np.maximum(m, 1e-9)),
        1.0 / np.maximum(m, 1e-9),
        np.sin(angle_rad),
        np.cos(angle_rad),
        np.sin(2.0 * angle_rad),
        v * np.cos(angle_rad),
        v * np.sin(angle_rad),
    ])

3.2 Model Pipeline Assembly (backend/train_model.py)

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, FunctionTransformer, PolynomialFeatures
from sklearn.linear_model import Ridge

physics_poly_pipeline = Pipeline([
    ("physics_expand", FunctionTransformer(physics_feature_expansion, validate=False)),
    ("scaler", StandardScaler()),
    ("poly", PolynomialFeatures(degree=3, include_bias=True)),
    ("ridge", Ridge(alpha=0.01)),
])

3.3 Two-Piece Asymmetric Power Spline Reconstruction

Unlike vacuum parabolas which are strictly symmetric about their midpoint, atmospheric drag causes continuous kinetic energy loss, resulting in an apex shifted past 50% of the trajectory and a steep terminal descent angle. The continuous flight profile y(x) is synthesized without running an ODE: 

def reconstruct_path(R: float, H: float, apex_x: float, n_pts: int = 80):
    apex_x = min(max(apex_x, 0.01), R - 0.01)
    ratio = apex_x / R
    p_asc = float(np.clip(1.0 / ratio, 1.35, 2.0))
    p_desc = float(np.clip(0.85 / (1.0 - ratio), 2.0, 3.0))

    # Ascent segment (0 -> apex_x)
    xs_asc = np.linspace(0.0, apex_x, n_pts // 2)
    ys_asc = H * (1.0 - ((apex_x - xs_asc) / apex_x) ** p_asc)

    # Descent segment (apex_x -> R)
    xs_desc = np.linspace(apex_x, R, n_pts - n_pts // 2)
    ys_desc = H * (1.0 - ((xs_desc - apex_x) / (R - apex_x)) ** p_desc)

    return np.concatenate([xs_asc, xs_desc[1:]]), np.concatenate([ys_asc, ys_desc[1:]])

4.2 Analysis & Discussion

  1. Non-Linear Underfitting of Linear Models: The naive simple_linear baseline failed with an R² of ~0.54 and an average range error exceeding 510 meters. This quantitatively confirms that quadratic velocity damping cannot be modeled linearly.
  2. Physics-Informed Performance: The proposed physics_poly model reached an R² of 0.9991, reducing range error to 22.3 m across distances spanning over 6,000 meters, while maintaining an execution speed of 0.266 ms (3.9x faster than numerical ODE).
  3. Decision Tree Latency: The single decision tree achieved 0.056 ms inference latency (18.6x faster than numerical ODE), making it ideal for micro-avionics applications.

5. Conclusion & Future Scope

5.1 Conclusion

The project successfully designed, implemented, and validated a physics-informed Machine Learning surrogate for ballistic flight dynamics with quadratic aerodynamic drag. By transforming raw kinematic parameters into an aerodynamic basis, the physics_poly model delivers near-perfect accuracy (R² > 0.999) and sub-millisecond inference speeds. The full system is deployed both as a local FastAPI inference service and as a standalone client-side application accessible globally via GitHub Pages.

5.2 Future Scope

  • 6-DOF Aerodynamic Dynamics: Extending point-mass equations to six degrees of freedom to incorporate projectile spin, Magnus force, and crosswind gust fields.
